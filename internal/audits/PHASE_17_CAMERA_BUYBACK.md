- 買取商店の robots.txt は「Crawling is allowed」（/api/・/mypage/・/cart などだけ禁止）。カメラの一覧は
  /category/2/368（デジタルカメラ・153件）と /category/2/108（デジタル一眼・228件）で、静的な HTML の構造化データ
  （schema.org の Product）に商品名・JAN・新品の価格・商品ページの URL が載る。?pageno= を変えても同じ内容（1ページに全件）。
- 商品ページ（例 /products/detail/22388）に「JAN: 4547410554281 … 新品 ¥260,000」。一覧の「★印なしのみ」はほぼ全商品に
  付く。店の「買取時のご注意事項」（https://www.kaitorishouten-co.jp/guide。2026-10-08 確認）に、家電は新品未開封品のみ
  買い取り、保証書に記入・捺印・シールのある商品は新品として買い取れない（一部例外あり）とある。つまり「★印なし」は保証書に
  印の無いことで、この店の新品の定義そのもの（iPhone・PS5・Switch 2 の既存の確定の買取も同じ条件）。会員・クーポン・
  まとめ売り・持込のような条件つきの価格ではない。条件つき価格（ネットオフ）を除く規則は維持。
  注意: 公式の直販で買ったときに保証書へ販売店の印・購入日が入るかはストアごとに確かめていない（売るときは保証書の記入の
  有無を確かめる必要がある。§7）。
- 6商品の商品ページ（/products/detail/22388・24408・26434・25561・16562・20463）をブラウザで開き、「JAN」と「新品 ¥…」が
  一覧の構造化データの JAN・価格と一致することを確かめた（2026-10-08。¥260,000・¥200,000・¥240,000・¥227,000・¥420,000・
  ¥450,000）。商品ページの価格は JavaScript で描画されるので、取得は一覧の構造化データを読む。構造化データに
  itemCondition があって新品でない行・円でない行は使わない。
- 店頭買取と郵送買取があり、「買取予約承認後の価格を保証（郵送=承認当日発送 / 店頭=当日ご来店）」。郵送の送料の明記は
  無いので、利益の計算は既存の前提（買取店への発送 ¥1,000・振込手数料 ¥300・移動 ¥500）のまま（iPhone などと同じ）。

## 4. 失敗したとき（手順21・22）

`update_buyback_prices.keep_manual_on_failure`: カメラの6商品（`KEEP_PREVIOUS_ON_FAILURE`）は、一時的な取得の失敗（通信・
HTTP 5xx・空のページ）のときだけ、前回の自動取得の行を価格・取得時刻を変えずに残す。前回の価格を否定する失敗
や、取りに行けない状態が続く失敗（403・429・robots の禁止）では残さず、失敗の行を書く（残すのは `TRANSIENT_FAILURES` だけ）。時刻を進めないので、14日を過ぎれば古い価格として確定から外れる。
既存の商品（iPhone・ゲーム機など）の扱いは変えていない。

## 7. 残している点（Low）

- GR IV 系の JAN は店の構造化データの値（公式のページで JAN を確かめられていない）。商品名の条件と、版ごとに別の JAN で照合する。

  ストアごとに確かめていない（iPhone・PS5 などの既存の確定の買取も同じ前提）。
- X100VI の売値は公式で買う版（シルバー 2025版）の行だけ。ブラックを買う場合の売値（¥250,000）は表示していない。
- 抽選の利益案件（GR IV HDF）は、抽選の受付が終わっていても「抽選」として出る（以前からの挙動。受付の状態との結び付けは別の Phase）。
