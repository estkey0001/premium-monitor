## 3. 設計だけのもの

### 画像だけの告知

- 対象: 店舗の告知の本文に日程が無く、画像の中にだけ書かれているもの（今は `announcements` に「日程が本文に無い」として残る）。
- 前提: 画像の利用許諾（店舗の規約で複製・解析が認められること）と、画像認識の API の規約・費用の確認。どちらも未確認なので実装しない。
- 設計: 画像は公開しない・保存しない（解析のために一時的に読むだけ）。読み取った値は本文の根拠と同じ形（画像 URL・取得時刻・読み取った文字）で非公開に残す。
  判読できない項目は UNKNOWN。年・時刻・価格を補わない。人の確認を通るまで公開しない。

### 店舗からの情報提供フォーム

- 受け付ける項目: 店舗名・支店名・公式告知の URL・商品・販売価格・応募期間・応募条件・連絡先（非公開）。
- 公開の前に: 店舗の実在（運営者の証拠）・告知 URL が店舗の公式ドメインか・告知の本文が提供内容と一致するか、を人が確かめる。即時公開しない。
- 今回はフォームを作らない・公開しない・店舗に連絡しない。

### 更新ジョブの分割

| ジョブ | 内容 | 間隔の案 |
|---|---|---|
| 商品発見 | 公式の商品一覧・API の差分 | 日次 |
| 抽選発見 | レジストリの一覧の差分＋（契約後）検索 | 日次 → 承認後に短間隔 |
| 抽選状態 | 受付前・受付中の告知の再取得（締切変更・中止・早期終了） | 日次 → 承認後に数時間ごと |
| 買取価格 | 買取の取得元 | 日次 |
| 二次流通 | 成約の台帳（人の記録） | 手動 |
| 公開生成 | 上の出力から公開 JSON・ページを作る | 各ジョブの後 |

- 古い結果による上書きを防ぐ: 各ジョブは出力に「入力の生成時刻」と「実行の開始時刻」を書き、公開生成は、今ある出力より古い開始時刻の結果を採用しない。
- 部分出力の公開を防ぐ: 各ジョブは一時ファイルに書いてから置き換える（`write_json_atomic`）。公開生成は、ジョブの完了印（同じ実行 ID）がそろった入力だけを読む。
- 同じジョブの重複実行は GitHub Actions の concurrency group で 1 つにする。
- 日次と短間隔の違い: 検出遅延は今の中央値 約 21 時間（1 日 1 回）→ 1 時間ごとなら最大 1 時間程度。ただし各取得元へのアクセスは 24 倍になる。
  規約・取得の制限・費用を優先し、短間隔は取得元ごとに許可を確かめてから。定期実行の追加・変更は今回していない。

## 4. 公開する情報の規則（実装済み）

- 公開しない: 応募条件の原文（eligibility_text）・支払い方法の原文・価格の行の原文（price_text）・発送時期の原文・条件の根拠の行・other_conditions。
- 公開する: 構造化した値（会員の種類と登録期限、購入履歴の期間と金額、X のフォロー・リポスト、アプリ限定、応募と購入の上限、地域、購入時の本人確認）。
  真偽は「必須」「不要と明記」「不明」の 3 つ。不明は表示しない。
- 件名（商品名・告知の見出し）は商品と告知の識別に使っている。出すかどうかは人の判断待ち。
- 応募ボタンは、TCG ハブと抽選ページの両方で `action_url.classify` の判定（取得元ごとに確かめた応募ページの形）だけで出す。
