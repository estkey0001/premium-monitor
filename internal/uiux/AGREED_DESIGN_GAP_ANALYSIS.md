# 合意済みデザインと現状のギャップ（2026-10-02）

> **位置づけ（2026-10-03 更新）**: 2026-10-02 時点のギャップ分析（スナップショット）。Phase 0 / 0.1 / 0.2（データの正確さ・表示の信頼性・二次流通の価格の意味）は完了。UI の設計の正本は UI_VIEW_MODEL_SPEC.md。

比べるもの:
- **合意済みデザイン**: 「今日どの商品を、どこで買い、どこで売れば、いくら利益になるか」を短時間で判断できる情報サイト。Webサイトのまま、UIと操作感を現代的にする。
- **現状**: 旧UI（`daily_lp_generator.py`、約9,800行、公開 HTML 577KB）と、新UI 段階B（`?ui=new`、`src/content/ui/`）。

判定: ◯=合っている、△=一部だけ、✕=合っていない・無い、⛔=UI だけでは解決できない（データが先に要る）

## 6. 横断的なルール

| 合意済み | 現状 | 判定 |
|---|---|---|
| 鮮度を偽らない（no fake freshness / no manual timestamp refresh） | E5（Apple の固定値に毎日の日時）、E6（時刻の書き換え）、公式価格の観測時刻が「今」、データ品質の集計が実態より良く見える | ✕ |
| 偽の価格を出さない（no fake price） | E1〜E4 が公開中 | ✕ |
| 締切を推測しない（no inferred deadline） | 抽選は守れている | ◯ |
| 在庫を偽らない（no fake availability） | Apple は常に在庫あり、RICOH は不明を在庫ありにする、予約を在庫ありと扱う | ✕ |
| 出品価格を成約価格として扱わない | comparator・eBay の型の取り違え・API の出品に成約の型を付けるコード（無効化中） | ✕ |
| 公式と言えないものを公式と言わない | 旧来の抽選の RICOH の固定定価が auto_scraped になっている | ✕ |
| 運営者向けの情報を一般の画面から外す（一般には「一部情報の更新が遅れています」程度） | 旧UIに Health タブ・取得統計・HTTP 403・EBAY_APP_ID などが出ている。新UIは出していない | 旧UI ✕ / 新UI ◯ |
| PC とモバイルで情報を削らない | 旧UIはモバイルで Health をドロワーから外している。新UIは同じ情報 | 新UI ◯ |

## 7. まとめ

- **UI だけで作れるもの**: HOME の2段の導線、ジャンルの状態の保持、ナビの組み直し、表とカード、ページ送り、並び替え、小さな検索、商品詳細の枠、各状態の表示（空・stale・未取得・未発表・日程要確認）。
- **データが先に要るもの（⛔）**: 利益の定義の統一、売値の種類の区別、成約データ（期間・件数つき）、出品の最安値・最高値、同一商品の照合の一本化、在庫の3つの項目、TCG 以外の予約・発売情報、価格の履歴、誤価格の除去（E1〜E7）。
- **新UIで今すぐ守れるもの**: 「出品で売値を代用しない」「未取得・未発表の表示」「運営者向けの情報を出さない」。データが無い部分は「未取得」と正直に出し、mock のデータで画面を先に完成させる。
