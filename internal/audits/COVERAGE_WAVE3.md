## 1. 仕入れ値の証拠（`retail_lookup.price_evidence`・Stage A / B / I / K）

表示価格と実際の取得価格を分ける。

| 項目 | 扱い |
|---|---|
| `listed_price` | 表示されている現金の税込価格 |
| `immediate_discount` | **誰でも・即時に**適用される値引きだけ（取得器が条件なしと確かめたものだけ） |
| `required_coupon` / `member_only` / `limited_quantity` / `campaign_conditions` / `campaign_price` | 条件つきの値引き。**現金の仕入れ値に使わない**（`price_conditions` に残す） |
| `points` / `cashback` | **現金と同額として控除しない**。別の項目として残し、`spread_if_points_counted`（参考の差）にだけ使う |
| `effective_price`（現金の仕入れ値の根拠） | 条件なし → `listed − immediate_discount` ／ 条件つきで通常の価格が分かる → `regular_price` ／ 条件つきで通常の価格が不明 → `listed_price`（`price_basis = CONDITIONAL_UNKNOWN_REGULAR`。高優先にしない） |

- 例: 商品 100,000 円・ポイント 10,000 円 → `effective_price = 100,000`（90,000 と自動確定しない）。ポイントだけで価格差が正に見える候補は REJECTED（NO_SPREAD）
- Samsung の一覧の価格はキャンペーン割引込みのことがある → `campaign_conditions` を付け、通常価格を別に持たない限り高優先にしない
- 複数の取得元で引けたら、MATCHED のうち**条件なしの価格を優先し**（次に通常価格が分かる条件つき・通常価格が不明の条件つきの順）、同じ条件なら現金の仕入れ値が最も安いものを返す。他は `alternatives` に残す
- 仕入れ元の種別: `OFFICIAL_DIRECT` / `AUTHORIZED_RETAILER` / `LARGE_RETAILER` / `EC_RETAILER` / `OUTLET` / `SECONDARY_NEW`（型だけ。実装は OFFICIAL_DIRECT のみ）

## 2. 調査候補（`apply_lookups`・Stage J / L）

`RETAIL_TO_BUYBACK` の経路。RESEARCH_CANDIDATE の条件: 同一性が完全一致（JAN・部品番号）・仕入れ値が新しい（36 時間以内）・買取側が新しい（3 日以内）・価格差が正。
**即 confirmed にしない**（VERIFIED は既存の判定だけ）。理由として残す: `OFFICIAL_UNVERIFIED`・`PURCHASE_SHIPPING_UNKNOWN`・`STOCK_UNKNOWN`・
`ACQUISITION_CONDITIONAL`（条件つき）・`BUY_STALE`・`IDENTITY_PARTIAL`・`PRICE_ANOMALY_SUSPECTED`。条件つき・買取が古い・割引込みは高優先にしない。

## 3. 取得器の追加（Stage E / F / G）

- **Apple 公式**（`AppleStoreAdapter`）: 機種のページの商品データの**部品番号の完全一致**。買取店の名前に部品番号（○○J/A）がある行（買取の一覧は JAN も持つが、
  Apple の一覧に JAN は無いので部品番号で引く）。容量違い・色違いは部品番号が別なので取り違えない。在庫は UNKNOWN（在庫ありにしない）。iPhone 18 系を正本に一括登録していない（調査候補としての照合だけ）
- **Canon**（`CanonStoreAdapter` + `config/canon_codes.yaml`）: **JAN → 商品コード**は、公式の製品ページ（personal.canon.jp）で確かめた表だけで引く（許可リスト方式。
  整備済みの別コード・販売終了・発売前を載せない）。購入ページ（store.canon.jp/online/g/g<コード>/）は構造化データの価格・無ければ「ご注文概要 価格」。
  ボディーとキットは JAN も商品コードも別なので、ボディーの価格をキットに流用しない。在庫は納期の文言から作らない
  - 表は 20 行（ボディー 11・キット 9）。公式の製品ページとの突き合わせは本書の「9. 検証ログ」
- 取得は全て `scripts/recheck_official._fetch`（polite）。商品ごとのページを取る取得器（Sony・Canon）は 1 実行あたり 4〜5 件に上限

## 10. 限界・残り（Wave 4 の候補）
