## 2. 同一性の規則（src/market/official_registry.identity_state）

- **IDENTITY_CONFIRMED**: 型番か JAN が config/products.yaml に登録され、その値を公式ページで確かめた証拠
  （IDENTITY_EVIDENCE: URL・確認日・版・セットの有無）がある。登録と証拠が食い違えば確認済みにしない。
- **PARTIAL_IDENTITY**: 型番・JAN の登録はあるが公式の証拠が無い（カメラの型番など。ボディ / キットの区別の証拠が無い）。
- **AMBIGUOUS**: 型番も JAN も無い（商品名・容量・SIM フリーなどで照合している）。
- **DISCONTINUED**: 公式で販売終了（OFFICIAL_NOT_SOLD）。
- **NEEDS_USER_DECISION**: 公式の情報でも、この商品がどの版か決められない（USER_DECISIONS）。

商品名だけ・価格の一致だけ・発売年だけで版を決めない。容量違い・国内版と海外版・セットと単体を同じ商品にしない
（買取商店の行の照合 ROW_RULES は版・セット・容量を区別する。テストで確認）。

## 7. 公式 URL の不具合（手順32〜35）

`beginner_deal_scanner._get_official_url` は、存在しないテーブル名（product_source_configs）を引いて例外を握り
つぶしていた（Apple は既定のストアのトップ、それ以外は常に空）。正しいテーブル（product_source_config）の、確認済み
（verified）で URL のある行を引くように直した（無ければ以前の既定）。

影響を受ける商品（確認済みで購入ページ（link_type が item）の公式 URL がある4件）:

| 商品 | 公式 URL（前 → 後） | 送料 | 利益の判定 |
|---|---|---|---|
| iPhone 17 256GB・AirPods Pro 3 | Apple ストアのトップ → 購入ページ | 同じ（Apple の送料無料） | 変わらない |
| PS5 Pro・Switch 2 | 空 → 公式の購入ページ | 同じ（商品ごとの送料の記録） | 変わらない |

Nikon Z8・Fujifilm X100VI の確認済みの URL は製品ページ（category）なので「買う」に使わない（空のまま。監査で直した）。
再確認で価格が変わった・販売終了になった行も使わない。

テスト（test_official_url_fix_does_not_change_shipping）で、確認済みの記録の全件の送料が前後で同じことを確かめた。変わるのは
「買う」のリンクが具体的になることだけ。同じテーブル名の不具合は src/pipeline/quality_checker.py にもあるが、
直すと「公式購入 URL が未設定」の指摘が増えて初心者向けの案件の格下げにつながりうる（影響が別）ので、変えていない。

## 8. 公式の再確認（手順44〜53）

- `scripts/recheck_official.py`: 確認済みの商品のうち、公式ページの静的な HTML で型番・価格（・在庫）を読み取れる
  もの（PS5 Pro: Sony Store の購入ページ、AirPods Pro 3: Apple の構造化データ）だけを、取得の共通の作法（robots.txt・
  同じドメインの間隔・正直な User-Agent）で取り直す。My Nintendo Store は JavaScript で描画する（静的な HTML に価格・
  在庫が無い）ので対象外。45商品に一度に広げない。
- 結果: unchanged / changed / sale_ended / failed / blocked と、明示の在庫の表示。exports/official_recheck/latest.json と
  history.json（直近300件）。
- 反映（audit_official_sources.apply_recheck）: unchanged なら価格を確認した日を取得した日に進める（本当の観測）。
  changed・sale_ended なら確認済みの定価を外す（人が確かめるまで確定に使わない）。在庫は明示の表示だけを取得の
  時刻つきで記録する。failed・blocked では何も変えない（前回の価格は消さず、確認日も在庫の時刻も進めない。古い在庫は
  期限で在庫未確認に戻る）。
- 読み取りの厳しさ（監査で直した）: Sony Store は「型番 → 在庫の欄（入荷待ち・在庫切れ・在庫あり・販売終了）→ 価格」
  の並びのときだけ価格を採用し、販売終了もこの商品の在庫の欄で判定する（ページの別の場所の「販売終了」や、型番の
  後に並んだ付属品の価格を拾わない）。Apple は sku が型番と一致する offer だけ（offers の形が配列・1件・@graph の
  どれでも読む）。別の URL へ移動した（リダイレクト）ページは読まない（moved）。
- 反映の条件（監査で直した）: 結果の URL・型番・記録の価格が、今の記録と同じときだけ反映する（記録を直した後の古い
  結果で反映しない）。確認日は記録より新しく、今日より未来でない日だけ。changed・sale_ended では、公式の購入ページの
  「確認済み」の印も外す（product_source_config の extra_config の verified を false・recheck_status）。「買う」の
  リンクは、確認済み・販売中・購入ページ（link_type が item）の行だけ。
- CI: 「Official recheck」のステップ（公式の確認の監査の直前）。取得は2件（別のドメイン）。直前のステップ（公式の
  価格の取得）が同じ取得元（www.apple.com など）を取ったばかりかもしれないので、取得元ごとの最初の取得の前に
  その間隔（rate_limit_sec など。Apple は120秒）の分を待つ。CI は約2分延びる見込み。
- 頻度: 価格は今の日次の CI で足りる（公式の価格はめったに変わらない。期限は price_evidence の基準のまま）。在庫は
  本来数時間ごとが望ましいが、CI の頻度は変えていない（変えるならユーザーの判断）。
- 再確認の計画: `python scripts/recheck_official.py --plan`（価格と在庫の期限を分けて一覧にする。ネットワークに出ない）。

## 10. 結果

- 同一性の確認済み 1 → 3（PS5 Pro・Switch 2・AirPods Pro 3）、曖昧 4 → 2、型番なし 23 → 22、JAN なし 45 → 43。
- 公式 URL の不具合を直した（送料・利益の判定は変わらない）。
- 公式の価格・在庫の再確認を、PS5 Pro と AirPods Pro 3 で自動にした（PS5 Pro の在庫は毎日の CI で新しくなる）。
- 確定の買取・確認済みの定価は、判断待ちの3商品が決まるまで増えない。
