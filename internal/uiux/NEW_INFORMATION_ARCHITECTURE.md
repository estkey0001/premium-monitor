# NEW INFORMATION ARCHITECTURE（新しい情報設計）

## 0. 方針

- サイトの目的を「機能がたくさんあるサイト」から「**今日何をすればいいか一瞬で分かるサイト**」に変える
- 一番大事な価値は2つ
  - TCG: **応募すべき抽選**
  - 物販（せどり）: **買うべき商品**
- 機能は削らない。**置き場所と見せ方だけを変える**
- 運用者向けの情報は一般ユーザーの画面から外し、`/admin/` にまとめる
- バックエンド・AI・利益計算・TCG判定のロジックは変えない。表示層だけを作り直す

## 0.1 UI Phase 1 の改訂（2026-10-03・正本）

段階B の構成（6つのタイル＋おすすめ TOP5、ナビ: HOME / 抽選・販売 / 利益商品 / 商品検索 / マイページ）を、
**ジャンル起点**の構成に置き換えた。下の §2・§3 は段階B の記録として残す（この節が優先）。
実装は `src/content/ui/`（navigation.py・categories.py・catalog.py・pages.py・styles.py）。

- **サイトの構造**: HOME / 利益商品 / 抽選・予約 / 在庫再開 / せどりルート（＋商品詳細は Phase 2 以降）
- **ジャンル**は独立した巨大タブにせず、URL の `category=` で HOME と各一覧の絞り込みに使う
  （スマホ / TCG / カメラ / ゲーム / PC / その他。products.genre などの読み替えは categories.py だけ）
- **HOME** は次の順番だけ。長いページにしない
  1. 小さなヘッダー（サイト名・情報確認の時刻・検索アイコン）
  2. ジャンルから探す（6つ。PC は 3〜6列、モバイルは2列。アイコン・名前・件数だけ）
  3. 目的から探す（利益商品・抽選・予約・在庫再開・せどりルート。件数と1行の説明）
  4. 小さな補助リンク（今すぐ狙う TOP10。買取急騰・新着商品は準備中）
- **ジャンルの保持**: HOME でジャンルを選ぶと `?category=camera`（UI Phase 8 から新UIが既定なので `ui=new` は付けない。古い `?ui=new&category=camera` も開ける）。目的・上部ナビ・ボトムナビで移っても保つ。
  HOME に戻ると外す。戻る・進む・直接の URL でも同じ表示になる
- **目的のページ**（Phase 1 は枠）: 現在地（HOME / カメラ / 利益商品）・ジャンルの切り替え（すべて＋6）・
  絞り込みの枠（キーワード・並べ替えは「準備中」で押せない）・一覧（実データ）・空状態・掲載の決まり（1行）
- **ナビ**: デスクトップは上部（HOME・4つの目的）、モバイルはボトムナビ5項目（HOME・利益・抽選・在庫・その他）。
  「その他」からせどりルート・ジャンル・検索・現行版へ。運営者向けの情報は一般のナビに出さない
- **件数の定義**（catalog.py の docstring が正本。Fake count 禁止）
  - 利益商品: 定価を確認済み（VERIFIED_*）・売り先が買取店・見込み利益 > 0 の「定価で買って買取店に売る」案件
  - 抽選・予約: runtime の状態で受付中・締切間近・まもなく開始・日程要確認（bucket < 99）。閲覧時に数え直す
  - 在庫再開: TCG の販売・入荷のうち、今買える（AVAILABLE_NOW）で古くないもの
  - せどりルート: main ルートのうち表示ガード（売値は買取か条件を満たした成約中央値）を通るもの。成約データが無い今は0件になりうる
  - ジャンルの件数 = そのジャンルの4つの目的の件数の合計

- 0件のタイルは消さず、灰色で「0件 ・ 次の予定: 10/5 開始」のように**次に起きること**を出す

### 3.2 おすすめアクション TOP5

1行1アクション。左にアクション種別、右に1つだけボタン。

| 種別 | 意味 | 色 |
|---|---|---|
| APPLY | 抽選に応募する | 緑 |
| BUY | 買う | 緑 |
| WAIT | 待つ（開始前・値動き待ち） | 橙 |
| SKIP | 見送る（利益が出ない・リスクが高い） | 灰 |

- 並べる順: 締切が近い APPLY → 検証済み BUY → WAIT。SKIP は最大1件（「見送ってよい理由」を伝える価値があるとき）
- 中身は既存の判定（TCG判定、利益ルート、AI Opportunities の exports）から取る。並べる順のルールだけを表示層で決める
- 参考値（stale、eBay未設定など）は BUY に入れない。「参考」として別に表示する

### 3.3 前回からの変化

「新しく受付開始 2件／締切が過ぎた 1件／値上がり 3件」。既存のポップアップ通知（買取急騰など）はここに移す。

## 4. 抽選・販売ページ

上から次の順で並べる。0件のグループは見出しだけ残して畳む（何が無いかも情報）。

1. 抽選受付中
2. 締切間近（24時間以内）
3. まもなく開始
4. 当選発表・購入期間
5. 日程要確認（情報が食い違っている・日付が不明）
6. 今買える
7. コンビニ
8. 再販
9. BOX（シュリンク付きかどうかを明記）
10. プレミア

- TCGとカメラ・ゲーム機の抽選を**同じ並び・同じカード**にまとめる。上部にフィルタ（すべて／ポケカ／ワンピース／カメラ／ゲーム機）
- 終了した抽選は一番下の「過去の抽選」に畳む
- 監視元の表・取得状況の表は `/admin/` に移す。一般向けには1行だけ「監視している公式サイト: 17か所（一部取得できていません）」

### 4.1 抽選カード

**いつも見せる（6項目）**

1. 商品名
2. 販売店（販売元）
3. 状態（バッジ1つ）
4. 締切とカウントダウン（例「10/3 23:59 締切 ・ あと1日4時間」。時刻が公表されていなければ日付だけ）
5. 価格
6. メインのボタン1つ（例「応募ページを開く」）

**開くと見せる（`<details>`）**

- 応募条件（原文）
- 支払い方法
- 購入期間
- 当選発表日
- シュリンクの有無
- 情報の確かさ（confidence）と情報源
- 最終確認日時・技術的な情報

## 5. 利益商品ページ

ランキング・せどりルート・初心者・Pro・AI Opportunities を1ページにまとめる。

### 5.1 タブ（並べ替えの切り替え）

| タブ | 並び順 | 既存の元データ |
|---|---|---|
| おすすめ | 検証済み → 確かさ → 利益額 | 利益ルート、AI Opportunities |
| 高ROI | 利益率 | 差益ランキング |
| 高利益額 | 利益額 | 差益ランキング |
| 高回転 | 売れやすさ（データがあるものだけ） | 既存の回転指標。無い商品は「データなし」 |
| 低リスク | 確かさが高く、価格の変動が小さい | 既存の confidence・freshness |

- 「検証済み」と「参考」を**同じ一覧に混ぜない**。参考は一覧の下に「参考（未検証）」として別に並べる
- 異常値（定価比 +500% 超、0円、stale）は一般表示から外し「確認中」にする。**判定ロジックは変えず、既存の除外フラグ・confidence を表示に反映するだけ**（閾値の新設が必要なら次フェーズで別途相談）

### 5.2 かんたん / 詳細（初心者・Proの置き換え）

初心者・Proを**別タブにするのをやめ、同じページの表示モードにする**。

| | かんたん（初期値） | 詳細 |
|---|---|---|
| カードに出すもの | 商品名、買う店→売る店、利益額、ボタン1つ | ＋利益率、全買取店比較、海外相場、手数料、確かさ、取得日時 |
| 表 | 出さない | 出す（モバイルではカードに変換） |
| 参考値 | 出さない | 「参考」ラベル付きで出す |

- 切り替えは右上のトグル。選んだモードは `localStorage` に覚える（失敗しても初期値で表示する）
- URLでも指定できるようにする（`?mode=pro`）

## 9. 状態（ステータス）の統一

### 9.1 抽選・販売の状態

| 状態コード | 表示文言 | 色 |
|---|---|---|
| OPEN | 受付中 | 緑 |
| ENDING_SOON | 締切間近 | 赤 |
| UPCOMING | まもなく開始 | 橙 |
| RESULT_PENDING | 結果待ち | 青 |
| WINNER_ANNOUNCED / WINNER_PURCHASE_PERIOD | 当選発表・購入期間 | 青 |
| UNKNOWN / 食い違い | 日程要確認 | 橙（枠線のみ） |
| CLOSED / ENDED | 終了 | 灰 |
| 発売予定（販売） | 発売予定 | 青 |
| 今買える（販売） | 販売中 | 緑 |

旧来の「近日開始」は「まもなく開始」に、「終了済み」は「終了」にそろえる。**状態コードの判定は変えず、文言と色の対応表だけを1か所にまとめる。**

### 9.2 データがないときの状態

| 状態 | 一般向けの表示 | 管理画面 |
|---|---|---|
| NO_DATA | 「まだ情報がありません。最終更新: ○月○日 ○:○○」 | 件数・理由 |
| NO_ACTIVE_EVENT | 「今受付中の抽選はありません。次の予定: ○○（10/5 開始）」 | — |
| SOURCE_BLOCKED | 「公式サイトの情報を取得できていません。公式サイトで直接確認してください（リンク）」 | 403 などの詳細 |
| COLLECTOR_ERROR | 「一時的に取得できていません」 | エラー全文 |
| NOT_IMPLEMENTED | 一般向けには出さない | 「未対応」 |
