## 4. M-3 買取の比較の基準

- 原因: 前回値が `data/manual_buyback_prices.csv`（CI は commit しない。最終コミット 2026-08-23）。PS5 Pro の前回 ¥134,500・X100VI の
  前回 ¥428,000 はどちらも 8 月の手入力の値で、毎日「+49% / −39%」の誤価格の警告になっていた
- 新しい基準: `exports/collector_report/price_baseline.json`（`src/collectors/price_baseline.py`）。直近の正常な自動取得の値・14日以内。
  手入力・取得失敗・隔離した行は入れない。基準が無い組（初めての観測・古くて捨てた）は前回比をしない。前回比 ±20% は警告だけで隔離の理由にしない
- **PS5 Pro の 200,700 円**: 買取商店の価格表（/kaden・更新 2026/10/21）の「プレイステーション5 Pro [CFI-7100B01] 2025版 ¥200,700」
  （[CFI-7000B01] も同額）で、キャンペーン・強化・条件の注記は無い。モバイル一番も同額。誤取得・別型番・条件つきではなく、
  **本物の型番行**だった。隔離の原因はカテゴリ共通の上限（ゲーム機 200,000）だけ（根拠は商品ごとではなく目安）
- 上限の扱い: カテゴリ共通の上限は目安で、**単独の店の値は採用しない**。上限を超える値は、次の全部がそろうときだけ採用
  （`above_genre_max_corroborated`）: その行が商品ページの URL（識別の番号まで付いたもの。一覧ページの根は不可）・照合済み・
  信頼度 high / medium と自動取得が明示されている・公式の価格の **1.5 倍以内**。別の店の行が、ホストも URL も別（同じ元の複製・
  同じ運営元は不可）・同水準（±10%）・同じ条件・公式の 1.5 倍以内・他の隔離の理由に当たらない。採用した価格は運営者向けの劣化アラート
  （price_adopted_over_ceiling）に出る（人が確認する）。3 倍以上・ゲーム機のスマホ価格帯・容量の逆転・下限未満は、裏付けがあっても
  隔離のまま（最初の案「別の店が±10%で公式の 2.5 倍以内」→ 2 倍 → 1.5 倍と、レビュー・監査の指摘で2回厳しくした）
- **PS5 Pro の結果**: 買取商店は商品ページの行（200,700）だが、モバイル一番は店のトップの URL の行なので裏付けにならない。
  **PS5 Pro の 200,700 は要確認（REVIEW_REQUIRED）のまま**（確定にしない）。運営者向けの劣化アラート（quality_gate_failure:ps5_pro）に
  出る。商品ページの行を出す別の店が同水準で現れれば、自動で採用される。人が確かめる場合の証拠は上のとおり（2026-10-21 に価格表を確認）
- X100VI の 260,000（前回比 −39%）: 前回 428,000 は 8 月の手入力。新しい基準では初めての観測なので比較しない。公式 315,700 より低く
  no_profit のまま（判定の理由が説明できる）

## 6. M-5 定時の実行の遅れ

- 直近 20 回の実行の測定: 予定 03:00 UTC に対し、作成時刻が 4:26〜7:06 遅れ（直近 10 回の schedule すべて）。Run は作成された時点で開始して
  いる（queue 待ちではない）ので、遅れは Run が作られる前（GitHub の定時の実行の混雑の可能性。ログからは断定できない）
- cron を 12:17 JST（UTC 03:17）へ（毎時 0 分を避ける）。頻度は上げない（1 日 1 回）。20:30 の確認とは矛盾しない
  （予定どおりなら 13:40 ごろ終わる。遅れても 20:30 より前）。実績の評価は数日後
