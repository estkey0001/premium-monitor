## 2. 受入の関門（`readiness.acceptance_gate`）

商品の通知の実送信は、変数の関門（Phase 23: 手動の実行・PRODUCT_REAL_SEND_ENABLED・本番の送信の旗・dry-run を外す・Telegram だけ・
設定）に加えて、受入の関門を必ず通す（CLI の dispatch-notifications の prepare と send が必ず `acceptance_env` を渡す）。

| 条件 | 内容 |
|---|---|
| 候補の指定 | `PHASE24_ACCEPTANCE_CANDIDATE_ID`（受入状態の候補の ID = 冪等性のキーの SHA-256 の16桁）。手動の実行のときだけ変数を読む。商品名・商品 ID・任意の値では送れない |
| 受入をまだ使っていない | 台帳に本番の商品の送信済み（ACCEPTED）・届いたか不明 / 前の実行の SENDING（UNKNOWN）が無い。出し直し待ち（IN_PROGRESS）なら同じ候補だけ |
| prepare | 今の受入状態が READY（または同じ候補の出し直し待ち）で、指定が今の候補（候補の ID・商品・台帳の記録・キー）に完全に一致。ほかの候補は READY（acceptance_not_selected）のまま |
| send | この実行の SENDING が指定の候補のキーの記録だけ（違えば送らずに READY に戻す）。送る直前の確かめ直し（期限・締切・利益・公式のページ）は outbox.send |

1回の受入で送るのは1件（Phase 23 の run ごとの上限1件と重ねる）。受入済みの後は、変数を戻し忘れても・同じ run の Re-run でも・
保留の候補や同じ候補を指定しても送らない。送れずに終わった（FAILED / EXPIRED / CANCELLED）後は、別の候補を明示して指定したときだけ
新しい受入になる（自動では移らない）。

## 3. 受入の状態（台帳から決める。変数は見ない）

| 受入の状態 | 台帳 | 受入状態の表示 | 送信 |
|---|---|---|---|
| NONE | 本番の商品の試行なし | WAITING / READY | 指定が候補に一致すれば1件 |
| SENDING | この実行の SENDING | — | 指定の候補だけ |
| IN_PROGRESS | 出し直し待ち（429・503） | PHASE24_ACCEPTANCE_IN_PROGRESS | 同じ候補だけ（既存の出し直しの決まり） |
| ACCEPTED | DELIVERED・届いたか不明を人が cancel で解決（届いていたかもしれない） | PHASE24_ACCEPTANCE_DONE（「本番受入済み。追加の送信は禁止」） | しない |
| UNKNOWN | UNKNOWN_DELIVERY・前の実行の SENDING | PHASE24_REVIEW_REQUIRED | しない（人が解決） |
| FAILED / EXPIRED / CANCELLED | 送れずに終わった（自動の判定で届いていないことが確か） | WAITING / READY | 別の候補の明示の指定が要る |

本番の商品の送信済み・届いたか不明・人が cancel で解決した記録は prune しない（受入の証拠。消えると受入の関門が外れる）。dry-run の記録は
今までどおり消す。outbox の run_prepare / run_send の受入の関門は既定で閉じる（環境を渡さなければ送らない）。外すのは
`NO_ACCEPTANCE_GATE` を明示したときだけ（関門の外の流れを確かめるテスト・検査だけ。CLI は使わない）。
