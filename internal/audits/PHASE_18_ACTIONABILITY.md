## 2. 判定の正本（`src/market/actionability.py`）

今すぐ行動できる = 確定の利益案件（opportunity.eligibility を通る）＋ 今の購入の経路（公式の具体的な購入・申込のページ）＋
今の購入の可否の証拠。判定はここだけ。画面（Python の生成・JavaScript）は結果（状態・ボタン・期限）を使うだけ。

| 種類 | 行動できる | 条件 |
|---|---|---|
| IN_STOCK | ○ | 在庫ありを確認してから3時間以内（`stock_state.STOCK_FRESH_SECONDS` を再利用。新しい期限は作らない） |
| STOCK_STALE（更新待ち） | × | 在庫ありだったが3時間を過ぎた（7日以内でも今すぐ買えるとは言わない） |
| OUT_OF_STOCK / UNKNOWN / SALE_ENDED | × | 在庫切れ・未確認・公式で販売終了 |
| LOTTERY_OPEN | ○ | 受付の開始〜締切の間（`tcg.lottery.schema.compute_lottery_status` を再利用）・公式のページで受付終了と出ていない・確認から7日以内で未来でない |
| LOTTERY_UPCOMING / LOTTERY_CLOSED | × | 受付前・締切後（ページの受付終了も） |
| LOTTERY_UNKNOWN | × | 締切が分からない・確認が古い・抽選の情報が無い（受付中と推測しない） |
| PURCHASE_PERIOD_OPEN | × | 当選者だけの購入期間（一般の人の当選が分からない） |
| PREORDER_OPEN / FIRST_COME_OPEN | ○ | 予約・先着の受付中（抽選と同じ条件） |
| PREORDER_CLOSED / FIRST_COME_CLOSED / UPCOMING | × | 受付終了・受付前 |

- 購入・申込のページ: 公式のストアごとに購入・申込のページの形を決めて（`_ACTION_PAGES`。Sony Store の購入ページ・
  Apple の /jp/shop/buy-・キヤノン /online/g/g・ニコン /shop/g/g・フジフイルムモール /shop/g/g・RICOH の ProductDetail（pid あり）・
  My Nintendo Store の /item/）、それに合うページだけ。一覧・トップ・紹介・クエリを付けただけのトップは使わない
  （missing_action_url）。抽選は申込の URL（entry_form_url）だけを使い、商品・一覧のページに切り替えない。
- 抽選の情報は、販売の方法・在庫の表示が抽選・予約のときだけ使う（通常販売の在庫ありを、過去の抽選の記録で上書きしない）。
  種類（抽選・予約・先着）が分からない行は受付中にしない。
- 受付中と言う条件（追加）: 開始と締切の両方が分かる（片方だけなら日程不明）・収集側の「状態の矛盾」（status_conflict。
  ページに受付終了とあるのに日付では受付中など）が無い・ページの状態が受付終了（英語・日本語）でない。時刻の無い日付は
  その日の中の時刻を推測しない（開始日の当日はまだ受付前・締切は日付のまま表示）。
- 在庫の表示: 確認時刻が無い・7日を過ぎた・未来（時計のずれの5分を超える）の在庫ありと在庫切れは在庫未確認。
- 期限（画面がボタンを消す時刻）: 在庫ありは確認から3時間、抽選・予約・先着は締切か確認から7日の早いほう。
- 抽選と商品の結び付け: 商品 ID か、型番（= ストアの商品コード）の完全一致だけ（`find_event`）。商品名では結び付けない。
  参考の項目（reference_only）は使わない。
- 行動できない理由（正本の名前）: not_profitable・identity_unverified・stock_out・stock_unknown・availability_stale・sale_ended・
  lottery_closed・lottery_not_open・lottery_deadline_unknown・lottery_evidence_stale・winner_only_period・preorder_closed・
  first_come_closed・missing_action_url。
- 期限は2つのまま（目的が違う）: 利益の案件の「在庫あり（○時点）」の表示と一覧の「在庫あり」の絞り込みは7日、
  今すぐ行動できる・在庫再開・商品詳細の「購入可能」は3時間。
- 利益商品に結び付ける抽選の情報は、LP の生成が読む抽選の情報（DB の受付中の抽選と `data/lottery_events.csv`）。
  人が公式のページで確かめて入れた行（取得元がブロックされたときなど）も、公式の URL・確認日時・受付期間があれば同じ規則で
  使う。確認日時は記録の値をそのまま使い、時刻だけ新しくしない（7日を過ぎれば受付中と言わない）。TCG の抽選の手入力の記録
  （`data/tcg_verified_lotteries.csv`）は TCG の画面の情報で、利益商品には結び付かない。

## 3. 画面

- 利益商品の一覧（PC の表・スマホのカード）: 状態のバッジ（購入可能・在庫切れ・抽選受付中・抽選終了・予約受付中・更新待ち など）、
  締切（終了なら「（終了）」）、詳細に「在庫（○時点）」と「今すぐ行動 できる/できない・状態（○確認）」・締切・行動できない理由。
  行動できるときだけ主ボタン（購入する・抽選に申し込む・予約する）。ボタンとバッジには生成時に決めた期限を付け、閲覧時に
  期限を過ぎていたらボタンを消し、バッジを「更新待ち」「抽選終了」などに落とす（判定はし直さない）。
- 商品詳細: 主要な数値に「今すぐ行動」の欄（できる/できない・状態・締切・確認時刻・理由）。行動できるときだけボタン。
- HOME: 「今すぐ行動できる利益商品 N件」（各商品の期限のうち閲覧時より後のものだけを数える）。
- 運営者向け: 「データの網羅」に「今すぐ行動」の行（確定の利益・行動できる・在庫・受付終了・更新待ち・日程不明・販売終了・
  購入ページ不明ごとの件数）と商品ごとの状態。

## 4. 通知

通知の生成（scripts/generate_notifications.py）は LP の生成より前に動くので、同じ実行の判定は使えない。診断
（exports/opportunity_diagnostics/latest.json）の `actionability.newly_actionable` に、前回の診断で行動できなかった商品だけを
通知の候補として記録する（同じ状態では毎回出さない。前回の診断が無いときは基準日として出さない）。通知への配信の結び付けは
今回はしていない（候補の記録まで）。在庫再開（OUT_OF_STOCK → IN_STOCK だけ）の規則は変えていない。

## 5. 公式の購入の可否の確認

静的な HTML で読める公式の再確認は Phase 16・17 のまま6商品（PS5 Pro・AirPods Pro 3・R5 II・Z8・iPhone 17・X100VI）。
在庫の表示を読めるのは PS5 Pro（入荷待ち）・Z8（在庫の欄。空なら記録しない）・X100VI（全色が同じとき）。Apple・キヤノンは在庫を
読まない（静的な HTML に根拠が無い）。JavaScript が要るサイトに Playwright を増やしていない。

## 6. レビュー・監査の指摘（対応済み）

- High: 状態の矛盾（status_conflict）・ページの受付終了（日本語）を受付中にしていた → 受付中にしない
- High: 開始日が無く締切だけ未来の行を受付中にしていた → 開始と締切の両方を要る
- High: 一般のページ（一覧・トップ・紹介・クエリ付き）を購入ページにしていた → ストアごとの購入・申込のページの形だけ
- Medium: 時刻の無い開始日の当日を受付中にしていた / 期限を過ぎても「できる」の文言が残っていた / 7日を過ぎた在庫切れを
  在庫切れのまま出していた / 結び付いた抽選の記録が通常販売の在庫ありより優先されていた → それぞれ直した
- Low: 未来の確認時刻の許容（5分）・申込のボタンの期限（確認から7日まで）・種類の分からない行・確認時刻の比べ方・
  診断の商品ごとの数え方・deploy-check の PC の表の行と mutation の検査・締切の日付だけの表示

## 7. 残している点（Low）

- 商品詳細の既存の「今の状態」（在庫の履歴・抽選の閲覧時の判定）と、新しい「今すぐ行動」（案件の在庫の確認時刻・抽選の CSV）は
  取得元が別なので、食い違うことがある。
- 一覧の「今すぐ狙う TOP10」と「在庫あり」の絞り込みは、これまでどおり7日の在庫の表示（data-stock）で決める。
- HOME の件数は、JavaScript が動かない環境では生成時の件数のまま（一覧・商品詳細は JavaScript が無いと表示しない）。

- 通知への配信（Discord など）は、候補（newly_actionable）の記録まで。配信の仕組みに結び付けるのは別の作業。
- 一覧・HOME の件数は1日1回の生成時の判定。閲覧時は期限で落とすだけで、新しく在庫が戻ったことは次の生成まで反映されない。
