# Coverage Wave 7a（TCG の応募先と完成度）

## 目的
告知のページがあるだけで「応募できる」と扱わない。応募の URL・経路・要件・完成度・定価との結び付きを、証拠のある分だけ分けて持つ。

## 実装
- `src/tcg/action_url.py`（新規）: `classify()` が 告知の URL・応募の URL・外部フォームの URL・経路・要件・完成度（complete / partial / review_required）を返す。
- `src/tcg/profit_dense.py`: 完成度を `action_url` に一本化。定価との結び付きに TCG の種類の一致と「仮の商品でない」を加えた。公開の集計に件数を追加。
- `src/research/candidates.py`: `COVERAGE_KEYS["tcg_profit_dense"]` に新しい件数を追加（公開してよい項目は件数だけ）。
- テスト `tests/test_coverage_wave7a.py`（14 件）・変異テスト `scripts/mutation_wave7a.py`（23 件）・deploy-check #878。
- 既存テスト `test_announcement_url_alone_is_never_actionable` は、応募の URL を取得元の公式ドメインに直した（旧前提「どのドメインの entry_url でも応募の URL」を意図的に厳しくした。削除・スキップはしていない）。

## 守ったこと
応募の URL を作らない・推測しない／日程を推測しない／名前だけの同一性を使わない／ブロックを回避しない／個別を公開しない／通知しない（分類は通信も通知もしない）。

## 実データの制約（PARTIAL の理由の候補）
受付中の主な取得元（カードラボ）の応募は SNS のフォロー＆リポストで、公式ドメインの応募ページが無い。ホビーステーション・麦わらストアは外部の LivePocket。
したがって公式ドメインの応募の URL が確認できるイベントは、手動で公式ページを確認して登録したものだけで、本番では 0 件のままになりうる。件数を作るために外部フォームを応募の URL に数えることはしない。

## 最終ゲートでの URL の安全の強化（reviewer / auditor の Medium を受けた修正）
- 許可リスト方式の `safe_https`（不可視文字・バックスラッシュ・符号化された `.` `/`・IP リテラル・punycode・不正なホストを拒否。dot segment・連続スラッシュ・既定ポート・fragment を正規化）。
- 告知・一覧・トップは query・大文字小文字・`..`・`index.html` を足しても応募の URL にしない（同一性は `_ident`）。応募の URL は出来事固有で、お知らせ系のパスでなく、公式の情報元の公式ドメインにあるものだけ。
- 外部フォームは `EXTERNAL_FORM_HOSTS`（取得元ごとの許可ホスト）だけ。告知と同じ URL を応募にする例外は `SELF_APPLICATION_SOURCES`（空。プレミアムバンダイは未確認）。
- 完成度の当選発表・購入期間は、日付として読めるものだけ「ある」。応募の URL が無くても日程・商品・経路がそろうものは `tcg_channel_ready`（運営者向けの別の件数。actionable ではない）。
- 変異テスト 55 件（見逃し 0）。

## 最終ゲート（2 回目）での追加修正
- 応募の URL は、公式ドメインに加えて取得元ごとの許可パス表（`APPLICATION_PATH_RULES`）に合うものだけ（公式ドメインの商品ページ・記事を応募にしない）。許可表に無い取得元は応募の URL を持たない。
- 外部フォームは `EXTERNAL_FORM_RULES`（ホスト + パスの形）。`/login`・主催者ページ・一覧は不可。
- 告知との同一性は `www.` の有無・符号化・`;` を畳む／拒否。`;`・埋め込み URL・`%25` は拒否。取得元の大文字小文字をそろえる。
- 範囲外の既存コード: `event_quality.with_action_url` は検証した応募の URL だけを数える。`update_alerts.py` は応募フォームが無いときのラベルを告知と分かるものに。
- 残るリスク: LivePocket の同じホストの別主催者のフォームは URL だけでは区別できない（運営者向けの件数にとどめ、行動の通知には使わない）。公式ホスト上のオープンリダイレクトは query の埋め込み URL の拒否までで、サーバー側の挙動は未確認。許可パス表の GEO・ポケモンセンター・福福トレカの形は、人が実際の応募ページで確認していない（確認するまで実データの応募 URL は 0 件のままになりうる）。
- 変異テスト 63 件（見逃し 0）。

## 最終ゲート（3 回目）での追加修正
- 告知の URL が、あるのに安全に読めない（http・大文字のスキーム・ポート・`;`・ゼロ幅・全角）ときは、応募の URL を確定しない（fail-closed）。外部フォームも同じ。
- 応募の URL・外部フォームの URL は query を持たない（捨てる）。非 ASCII・連続スラッシュは拒否。許可表のホストは完全一致、数字は ASCII（`[0-9]`）。照合は `fullmatch`。
- 許可表は GEO だけ（形は暫定・人が未確認）。会員ログインの福福トレカ・形が未確認のポケモンセンターは外した。
- 旧 CSV の通知経路（`scripts/update_alerts.py`）は、応募フォームの URL を `safe_https` で検証し、読めないものは告知ページへ落としてラベルも告知にする。管理画面の文言は「検証した応募の URL N件」。
- **残る（Wave 7a の範囲外・要判断）**: 顧客向けの「応募する」リンク（`src/content/ui/runtime.py:176`）は、人が確認した手動データの `entry_url` を旧来の公式ドメイン判定で出している。`classify` へ一本化するかはユーザーの判断（一本化すると、許可表に無い取得元の手動確認済みの応募リンクが顧客画面から消える）。
- 変異テスト 72 件（見逃し 0）。

## 最終ゲート（4 回目）での追加修正
- 旧 CSV 通知経路は、応募フォームを「応募ページを確認（公式ドメイン未照合）」と断定せずに示し、`url` も `safe_https` で検証（query は捨てる）。読めなければ告知へ・どちらも読めなければ URL もラベルも空。
- 告知の URL が無い・文字列でない `source_urls` の要素が混ざるときは応募の URL を確定しない。不正な `%`・LivePocket の予約語（login など）を拒否。

## 最終ゲート（5 回目）での追加修正
- 旧 CSV 通知経路: 5 回目で、query を捨てると実データ（RICOH の商品 ID・楽天ブックスの検索語）のリンクが壊れる劣化（私が入れたもの）を指摘され、**検証した URL の query は残す**ように戻した（`//` を含む query・HTML や引用符の文字は使わない）。告知と同じ URL は告知として扱い、別のフォームだけを「応募先の候補を確認（公式ドメイン未照合）」と示す。
- 応募の経路・`channel_ready` は、公式の情報元のときだけ登録簿から決める。告知の URL のホストは、その取得元の公式ドメイン（`official_url` / `lottery_url` / `news_url`）にあるときだけ確定の根拠にする。
- `safe_https` は HTML・引用符・シェルで意味を持つ文字（`<>"'`|^{}`）を拒否。LivePocket の予約語は大文字小文字を区別しない。
- 残る（Low・記録のみ）: 応募の URL とイベントの商品・日程の突き合わせはしていない（GEO の形は暫定。実運用で確定させる前に告知本文との突き合わせを足す）。旧 CSV 経路は取得元の公式ドメインの表を持たないので、任意の https ホストを「候補」として示す（ラベルで未照合と明示。入力は運営者が管理する CSV）。
