## 2. 候補の台帳（`src/discovery/store.py`）

- CI は毎回 DB を作り直すので、候補の正本は生成物としてコミットする台帳（`exports/discovery/product_candidates.json`・
  `event_candidates.json`）。中身は既存の `product_candidates` の表にも写す（既存の候補の仕組み・承認 / 却下の CLI を再利用）
- 候補の ID は発見元と同一性（Apple: 機種 + 容量・TCG: 公式の商品コード・告知: 発見元 + URL + 種類・抽選: lottery_id）から作る
- 見つけ直しても discovered_at は変えない。last_seen_on（日付）だけ進め、内容が変わったときだけ updated_at を進める
- 状態: NEW / PENDING_REVIEW / MATCHED_EXISTING / APPROVED / REJECTED / STALE / REVIEW_REQUIRED /
  ANNOUNCEMENT_REVIEW_REQUIRED / MATCHED_EVENT。人の判断（APPROVED / REJECTED）は発見で上書きしない
- 見つからなくなった候補は7日で STALE（すぐ消さない）。90日で STALE / MATCHED を消す（人の判断は残す）。読めなかった発見元の候補は
  STALE にしない
- 正本（config/products.yaml・products の表・official_registry）には書かない。承認しても台帳に記録するだけ（push しない）

## 3. Apple（iPhone）の発見（`src/discovery/apple.py`）

- 購入の一覧（/jp/shop/buy-iphone）から販売中の機種のページを見つけ、機種のページの商品データ（部品番号ごとの sku・partNumber・
  fullPrice・name）を読む。名前「iPhone 18 Pro 256GB Cosmic Orange」を機種・容量・色に分ける（世代・種類・容量を区別。
  「iPhone」という語だけでは判断しない。iPhone 以外の商品（AppleCare など）は読まない）
- 正本の「機種 + 容量」（色はまとめる）と照合: 一致 → MATCHED_EXISTING（候補にしない）・正本に無い → PENDING_REVIEW
  （部品番号・色・公式の価格・URL・発見日時を証拠に）・名前を読めない → REVIEW_REQUIRED
- 取得は既存の作法（`recheck_official._fetch`: robots.txt・同じドメインの間隔 120 秒・正直な User-Agent・リダイレクトを
  たどらない・403 は止める）。1回の実行で一覧1件と機種のページ最大2件（まだ読んでいない・正本に無い機種が先。残りは読もうと
  した日の古い順）。読めない機種が枠を使い続けない
- 失敗しても LP の更新は止めない（`continue-on-error`。報告だけ）。一覧を読めなければ台帳を変えない

## 4. TCG の発見（`src/discovery/tcg.py`。新しい取得はしない）

- 日程の無い告知（本文に日程が無い・PCO の本体が 403）: 捨てずに ANNOUNCEMENT_REVIEW_REQUIRED（14日を過ぎても残す）
- 一覧のタイトルだけで見つけた販売の告知（ポケモン公式のニュース。予約・先着・再販・読む上限で読まなかった抽選）:
  ANNOUNCEMENT_REVIEW_REQUIRED（本文は読まない。アダプタは既に読んだ一覧から記録するだけ）
- 日程つきの正式な抽選: MATCHED_EVENT（同じ告知を重ねない）。発売の予定: RELEASE（抽選にしない）
- 日程は推測しない（画像の文字を読まない・公開日を受付期間にしない・受付中にしない）。必要な項目: 公式の URL・タイトル・発見元・
  発見日時・足りない項目・理由
- 商品との結び付けは公式の商品コード（【XX-NN】）だけ。名前だけでは結び付けない
- 公式の一覧の商品（ポケモンの公式 API・ONE PIECE の商品の一覧）は TCG の商品の候補（TCG の正本は無い。商品コードが無ければ要確認）

## 8. レビュー・監査の指摘（対応済み）

- High（レビュー）: 14日以内の日程の無い告知は抽選の系統で仮のイベント（announcement_only）になっており、それを正式なイベント
  （MATCHED_EVENT）と扱って要確認の一覧から消していた → 日程の無い仮のイベントは要確認の告知にする
- Medium（監査）: 機種のページで 403 を受けても同じ取得元の次のページを読んだ → ブロック（polite.CUTOFF_IMMEDIATE）で打ち切る
- Medium（監査）: TCG の収集が失敗して前回の生成物が残っても候補を「今日見た」とした（鮮度の偽装と同じ型）→ 入力の generated_at が
  12時間以内でなければ見つけ直したことにしない・STALE にもしない
- Medium（レビュー）: Apple の一覧から機種が0件のとき・TCG の収集が失敗した日（空の生成物）・読めなかった取得元で候補を STALE に
  した → STALE にしない
- Medium（レビュー）: STALE で元の状態が消え、終わった抽選・発売済み・正本と一致していた商品が要確認の表に出た → `stale_from` を
  残し、確認待ちだったものだけ表示
- Low: 最初の取得の前に取得元の間隔を待つ・名前の形が変わったら候補を作らない・画面のリンクは公式のホストだけ・知らない種類を

  容量が2つのページに出ても安定・発売の予定の ID に日付を入れない・TCG を DB に写さない・DB の写しで人の判断の項目も更新
